# 일일 화면 수집·제한 재시도 흐름

## 목표와 완료 시각

- 목표: 공식 KBL 화면의 일일 수집 단계를 한 명령으로 실행하고, 일시적 실패는 해당 단계만 제한 횟수만큼 재시도한다.
- 완료: 2026-11-01 (Asia/Seoul)

## 구현 내용

- `app/services/daily_refresh.py`
  - 이름과 실행 함수로 구성된 각 단계를 독립적으로 실행한다.
  - 단계별 최대 시도 횟수를 1~3회로 제한한다.
  - 한 단계가 최종 실패해도 이후 단계는 계속 실행한다.
  - 단계별 시도 횟수, 성공 여부, 마지막 오류를 반환한다.
- `app/cli.py`
  - `refresh-daily --attempts 2 --game-limit 5` 명령을 추가했다.
  - 일정, 선수 시즌기록, StatsKing, Daily Picks, 완료 경기 쿼터·선수기록·문자중계 순서로 실행한다.
  - 최종 실패가 하나라도 남으면 종료 코드 1, 모두 완료되면 0을 반환한다.
- `app/collectors/official_pages.py`
  - 기록 링크는 나타났지만 문자중계 Q1~Q4 탭이 아직 준비되지 않은 경기를 오류로 처리하지 않고 건너뛴다.
  - 다음 일일 실행에서 같은 화면을 다시 확인한다.
- `tests/test_daily_refresh.py`
  - 실패한 단계만 재시도하는지, 최종 실패 뒤에도 다음 단계가 실행되는지 검증한다.

## 검증

```bash
python -m pytest -q
# 46 passed
python -m ruff check app tests
# All checks passed!
python -m app.cli refresh-daily --attempts 2 --game-limit 1
# 종료 코드 0
```

실제 공식 화면 제한 실행 결과:

- 일정 카드 33건 갱신
- 공식 선수 기록 7페이지, 137명 갱신
- StatsKing 경기 카드 3건 갱신
- Daily Picks 문제 5건 갱신
- 완료 경기 쿼터 점수 1건 저장
- 완료 경기 선수 박스스코어 24행 저장
- 문자중계 Q1~Q4가 아직 준비된 대상은 0경기였으며 정상 건너뜀
- 일곱 단계 모두 완료, 종료 코드 0

단계별 1회 제한 검증에서는 선수 시즌기록 화면이 일시적으로 페이지 탐색을 표시하지 않아 해당 단계만 실패했고, 나머지 단계는 계속 실행됐다. 이후 기본 2회 설정 실행은 정상 완료됐다.

## 외부 데이터와 안전 제한

- 공식 KBL 브라우저 렌더링 화면만 사용하고 내부 API는 직접 호출하지 않는다.
- 로그인, 선택, 응모, 제출을 수행하지 않는다.
- 재시도 횟수와 완료 경기 확인 상한을 CLI에서 제한해 무한 반복과 과도한 요청을 방지한다.
- 예약 실행 주기는 아직 설정하지 않았다. 사용자가 원하는 시각과 실행 환경을 정한 뒤 별도로 구성한다.
