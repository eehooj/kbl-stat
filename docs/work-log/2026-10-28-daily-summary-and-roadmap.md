# 2026-10-28 작업 요약 및 남은 작업

- 작성일: 2026-10-28 (Asia/Seoul)
- 범위: KBL StatsKing·Daily Picks·Weekly 6 정답 추천 시스템의 Phase 1 화면 기반 데이터 수집

## 오늘 완료한 작업

### 1. 내부 API 직접 호출 제거

- KBL 내부 API를 직접 호출하던 코드를 제거했다.
- 로컬 Chrome과 Playwright로 공식 페이지를 렌더링한 뒤, 화면에 표시된 텍스트만 읽도록 전환했다.
- 로그인·CAPTCHA·게임 제출·알림 발송은 수행하지 않는다.
- 원문 스냅샷의 해시와 수집 이력을 DB에 남긴다.

### 2. 시즌 리더 수집

- 명령어: `python -m app.cli collect-season-leaders`
- 공식 시즌 리더 화면의 선수 순위와 표시 지표를 저장한다.
- 실제 화면 검증에서 시즌 리더 130건을 수집했다.

### 3. 월별 일정·결과 수집

- 명령어: `python -m app.cli collect-schedule`
- 현재 표시 월의 날짜·시각·장소·두 팀의 표기 순서·점수·완료 여부를 저장한다.
- 완료 경기는 화면의 `기록` 또는 `하이라이트` 표시를 근거로 점수를 저장한다.
- 예정 경기의 화면상 `0-0`은 결과 점수가 아닌 미확정 일정으로 저장한다.
- 일정 카드에 홈/원정 라벨이 없으므로, 팀 표기 순서를 홈/원정으로 추정하지 않는다.
- 실제 화면 검증: 경기 49건(완료 41건, 예정 8건) 수집.

### 4. 이번 시즌 전체 일정 수집

- 명령어: `python -m app.cli collect-season-schedule --season 2026-2027`
- 공식 일정 화면의 월 이동 버튼으로 2026년 10월부터 2027년 5월까지 8개월을 순서대로 확인한다.
- 빈 달은 가상 경기를 만들지 않고 원문 및 수집 이력만 보존한다.
- 실제 화면 검증: 경기 282건(완료 41건, 예정 241건), 빈 화면 1개월 확인.

### 5. 팀 순위 수집

- 명령어: `python -m app.cli collect-team-rankings`
- 공식 팀 순위 표의 승·패·승률·승차·최근 5경기·연속·홈/원정 성적·다음 상대·상대전적을 저장한다.
- 실제 화면 검증: 2026-2027 정규시즌 10개 팀 성적 수집.

### 6. 데이터베이스·검증·저장소

- 화면 관측용 테이블과 Alembic 마이그레이션을 추가했다.
- 매 작업마다 원문 스냅샷과 수집 로그를 남긴다.
- 최신 기준 단위 테스트 8건 통과, Ruff 검사 통과.
- 오늘 작업 커밋은 모두 GitHub `main` 브랜치에 푸시했다.

## 현재 실행 방법

```powershell
alembic upgrade head
python -m app.cli collect-season-leaders
python -m app.cli collect-season-schedule --season 2026-2027
python -m app.cli collect-team-rankings
```

현재는 수동 실행이다. 정해진 시각에 자동 실행하는 스케줄러는 아직 추가하지 않았다.

## 남은 작업

### 우선순위 1 — 팀 세부 기록 화면 조사 및 수집

목표는 평균 득점·실점, 리바운드, 턴오버, 공격/수비 효율 등 Weekly 6 승패 예측에 필요한 지표를 공식 화면에서 확인·저장하는 것이다.

- 실제로 데이터가 표시되는 공식 화면과 표 구조를 먼저 확인한다.
- 화면에 확인된 지표만 DB에 추가한다.
- 페이지에 값이 없으면 추정하거나 다른 출처로 대체하지 않는다.

완료 조건: 팀별 세부 지표를 화면 원문과 연결해 재실행 가능하게 저장한다.

### 우선순위 2 — 경기 상세 화면 조사

목표는 홈/원정 라벨과 팀·선수 박스스코어가 실제 표시되는지 확인하는 것이다.

- 일정 카드의 팀 표기 순서를 홈/원정으로 가정하지 않는다.
- 상세 화면에 홈/원정 및 기록이 명시되어 있을 때만 기존 경기·팀 경기 기록 구조와 연결한다.

완료 조건: 화면 근거가 있는 경기만 홈/원정 및 세부 기록을 저장한다.

### 우선순위 3 — 예측 특성 계산

확보된 경기 결과와 팀 성적을 사용해 다음 값을 예측 기준 시점 이전 데이터로 계산한다.

- 최근 5/10경기 승률
- 휴식일과 연속 원정 여부
- 평균 득점·실점 및 확보된 팀 세부 지표
- 상대 전적

완료 조건: 계산 시점 이후의 경기 결과를 사용하지 않는 테스트를 포함한다.

### 우선순위 4 — Weekly 6 문제·결과 화면 수집

- 월요일 우선으로 공식 Weekly 6 화면의 등록 여부를 확인한다.
- 주차, 후보 경기, 마감, 선택지, 공식 정답과 채점 규칙이 실제로 보일 때만 저장한다.
- 미확인 규칙은 구현하거나 가정하지 않는다.

완료 조건: 확인된 한 주차를 원문 근거와 함께 저장하고 재실행 시 갱신한다.

### 우선순위 5 — 승패 예측 및 CLI 출력

- `predict-weekly6 --week YYYY-WW`에서 데이터가 충분한 경기만 추천한다.
- 추천팀, 양 팀 확률, 근거, 데이터 부족 여부, 신뢰도를 출력한다.
- 6경기 조합 확률은 독립성 가정의 근사치일 뿐임을 명시하고, 검증 가능할 때만 표시한다.

완료 조건: 가상 경기나 가상 확률을 출력하지 않고, 데이터 부족 시 명확히 중단 또는 안내한다.

### 우선순위 6 — 백테스트와 확률 보정

- 과거 Weekly 6 문제와 공식 정답이 화면에서 확보될 때만 수행한다.
- 개별 적중률, 주차별 적중 수, 전체 적중 비율, 확률 정확도, 단순 승률 기준선 비교를 측정한다.
- 미래 결과 유입을 막는 시점 고정 검증을 적용한다.

완료 조건: 백테스트 입력의 관측 시각과 결과 시각이 분리되어 재현 가능하다.

### 우선순위 7 — 자동 실행 설정

- 월요일 Weekly 6 확인 및 일별 기록 갱신을 Windows 작업 스케줄러 등 실행 환경에 맞게 설정한다.
- 과도한 요청을 피하도록 재시도 간격과 실행 상한을 둔다.
- 알림 발송과 게임 제출 자동화는 범위 밖으로 유지한다.

완료 조건: 사용자가 명시적으로 선택한 실행 주기에서만 동작하고, 화면 기반 수집 원칙을 유지한다.
