# Weekly 6 화면 후보 경기 수집

- 완료일: 2026-10-29 (Asia/Seoul)
- 목표: 공식 Weekly 6 화면에 표시된 후보 경기와 공식 선택 수를 추측 없이 저장한다.

## 확인한 화면

공식 Weekly 6 화면에서 다음 정보가 실제로 표시된 것을 확인했다.

- `Pick 1`부터 `Pick 11`까지의 후보 번호
- 각 후보의 날짜·시각, 경기장, 두 팀의 화면상 표기 순서
- `응모를 위한 6경기 중 0경기 선택` 문구

현재 화면에서는 후보 11경기 중 6경기를 선택하는 구조가 확인됐다. 화면에는 문제 고유 ID, 절대 마감 시각, 홈/원정 라벨, 공식 정답·채점 규칙이 보이지 않았다.

## 변경

- `collect-weekly6`가 표시된 Pick 후보를 파싱하도록 확장
- `weekly6_visible_fixtures` 테이블 및 Alembic 마이그레이션 추가
- 후보 번호·일시·장소·첫 번째/두 번째 팀 표기 순서를 저장
- 주차 식별자는 화면에 공식 ID가 없어 후보 경기의 최소·최대 날짜 범위로 만든 관측용 라벨을 사용
- 공식 선택 수를 저장
- 원문 스냅샷과 수집 로그를 함께 보관

## 의도적으로 저장하지 않은 값

- 팀 표기 순서를 근거로 한 홈/원정 값
- 화면에 절대 시각으로 표시되지 않은 마감 시각
- 화면에 보이지 않는 문제 고유 ID
- 공식 정답, 채점 규칙, 승리 확률

## 본문 미표시 보호

대표 화면 또는 브라우저 환경에서 Weekly 6 본문이 보이지 않을 경우, 이를 문제 미등록이라고 단정하지 않는다. `본문 미표시` 상태만 원문 및 수집 이력에 남기고 문제·후보·예측을 생성하지 않는다.

## 실행

```powershell
alembic upgrade head
python -m app.cli collect-weekly6
```

## 실제 검증

새 SQLite DB에서 현재 공식 화면을 렌더링해 확인했다.

- Weekly 6 관측 주차 1건 저장
- 후보 경기 11건 저장 (Pick 1~11)
- 공식 선택 수 6 저장
- 단위 테스트 13건 통과
- Ruff 검사 통과
- 빈 DB Alembic 마이그레이션 후 후보 테이블 생성 확인
